## 🔐 Connexion Google + Supabase (priorité haute)

### Objectif
Permettre aux utilisateurs de se connecter avec leur compte Google et de persister leur progression (scores, historique, questions vues) dans une base Supabase, quel que soit l'appareil.

### Architecture
- **Auth** : Google OAuth via Supabase Auth (popup ou redirection)
- **Base de données** : Supabase (PostgreSQL avec Row Level Security)
- **Client** : `@supabase/supabase-js` chargé via CDN (ESM importmap)
- **Fallback** : le système localStorage actuel continue de fonctionner si l'utilisateur n'est pas connecté

### Étapes d'implémentation

#### Étape 1 — Configuration Supabase
- [ ] Créer un compte sur [supabase.com](https://supabase.com) (gratuit)
- [ ] Créer un projet "quiz-attache-territorial"
- [ ] Récupérer `SUPABASE_URL` et `SUPABASE_ANON_KEY` (Settings > API)
- [ ] Activer Google Auth (Authentication > Providers > Google)
  - [ ] Créer un OAuth Client ID dans Google Cloud Console
  - [ ] Configurer l'URI de redirection (ex: `https://localhost:8080` en dev)
- [ ] Exécuter le SQL de création des tables (voir schéma ci-dessous)

#### Étape 2 — Création de `js/supabase-client.js`
- [ ] Initialiser le client Supabase avec `createClient()`
- [ ] Exporter les fonctions :
  - `signInWithGoogle()` → déclenche la popup OAuth
  - `signOut()` → déconnexion
  - `getCurrentUser()` → récupère l'utilisateur connecté et crée son profil si première visite
  - `onAuthChange(callback)` → écoute les changements d'état auth

#### Étape 3 — Création de `js/supabase-sync.js`
- [ ] `saveQuizSession(sessionData)` → sauvegarde une session et ses réponses
- [ ] `getQuizHistory(userId)` → récupère les 20 dernières sessions
- [ ] `getChapterStats(userId, chapterId)` → stats par chapitre

#### Étape 4 — Modification de `index.html`
- [ ] Ajouter l'`importmap` dans le `<head>` :
  ```html

    "imports": {

  </script>
  ```
- [ ] Ajouter une section d'auth dans le header de l'accueil (bouton "Se connecter avec Google")
- [ ] Afficher l'avatar et le nom de l'utilisateur connecté
- [ ] Passer les scripts en `type="module"`

#### Étape 5 — Modification de `js/app.js`
- [ ] Importer les fonctions Supabase au début

- [ ] Dans `showResults()` : après l'affichage, appeler `saveQuizSession()`

#### Étape 6 — Sécurité (RLS)
- [ ] Vérifier que les politiques Row Level Security sont actives sur toutes les tables

### 📋 Schéma SQL des tables Supabase

```sql
-- Table des profils utilisateurs
CREATE TABLE profiles (
  id          UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  email       TEXT,
  name        TEXT,
  avatar_url  TEXT,
  created_at  TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE profiles ENABLE ROW LEVEL SECURITY;

CREATE POLICY "users can view own profile"
  ON profiles FOR SELECT USING (auth.uid() = id);
CREATE POLICY "users can insert own profile"
  ON profiles FOR INSERT WITH CHECK (auth.uid() = id);
CREATE POLICY "users can update own profile"
  ON profiles FOR UPDATE USING (auth.uid() = id);

-- Table des sessions de quiz
CREATE TABLE quiz_sessions (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id         UUID NOT NULL REFERENCES profiles(id),
  chapter_id      TEXT NOT NULL,
  mode            TEXT NOT NULL,
  question_count  INT NOT NULL,
  score           INT NOT NULL,
  max_streak      INT DEFAULT 0,
  started_at      TIMESTAMPTZ DEFAULT now(),
  completed_at    TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE quiz_sessions ENABLE ROW LEVEL SECURITY;

CREATE POLICY "users can view own sessions"
  ON quiz_sessions FOR SELECT USING (auth.uid() = user_id);
CREATE POLICY "users can insert own sessions"
  ON quiz_sessions FOR INSERT WITH CHECK (auth.uid() = user_id);

-- Table des réponses individuelles
CREATE TABLE quiz_answers (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  session_id      BIGINT NOT NULL REFERENCES quiz_sessions(id) ON DELETE CASCADE,
  question_id     TEXT NOT NULL,
  selected_option INT NOT NULL,
  is_correct      BOOLEAN NOT NULL,
  answered_at     TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE quiz_answers ENABLE ROW LEVEL SECURITY;

CREATE POLICY "users can view own answers"
  ON quiz_answers FOR SELECT USING (
    session_id IN (SELECT id FROM quiz_sessions WHERE user_id = auth.uid())
  );
CREATE POLICY "users can insert own answers"
  ON quiz_answers FOR INSERT WITH CHECK (
    session_id IN (SELECT id FROM quiz_sessions WHERE user_id = auth.uid())
  );

CREATE INDEX idx_sessions_user ON quiz_sessions(user_id);
CREATE INDEX idx_answers_session ON quiz_answers(session_id);
```

## 📊 Améliorations complémentaires (priorité moyenne)

Ces améliorations peuvent être faites indépendamment, avant ou après Supabase.

### Mode révision
- Après le quiz, permettre de revoir toutes les questions avec leurs réponses
- Afficher la question, la réponse donnée, la bonne réponse, l'explication et la source
- Idéal pour apprendre de ses erreurs

### Statistiques cross-session (localStorage)
Même sans Supabase, on peut améliorer les stats en localStorage :
- Stocker l'historique des scores (date, thème, score, mode)
- Afficher un graphique d'évolution sur l'accueil
- Afficher le total de questions répondues global

### Feedback sonore
- "Ding" pour bonne réponse, "buzz" pour mauvaise
- Utiliser Web Audio API (pas de fichier audio à charger)
- Activable/désactivable depuis l'accueil
